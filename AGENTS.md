# Voidward – Agent Handoff

Co-op space roguelite vertical slice (1–4 players). Player docs: `README.md`. This file = dev context for AI agents.

## Gameplan (2026-10-13, issue #72)
The game is now a **journey home**: a moon mission (*SELENE-4*) falls into a wormhole, the crew wakes in M33 and flies through 5 Local Group galaxies (M33 -> M31 -> NGC 6822 -> Leo I -> LMC) home to Sol, upgrading the **warp drive** (Mk I-V, Home Drive) to shrink the **Home ETA**. Travel = flown warp flights (#73). Death = time loop back to M33 with meta kept (#74). Enemies: nature + aliens only (no pirates); Wardens = alien guardian species (#42). Collapse -> the Rift (finale only). Credits -> Salvage, Stardust -> Memory fragments.
- **Gameplay decisions follow #72 and its child issues, not the legacy code.** #46 (run structure: 5 galaxies, systems, galaxy map, suspend save; gates/Collapse removed) is in. #73 is split into #78 (crew warp drive), #79 (flown warp), #80 (cruise, hops) and #81 (finale), all done. #74 is split into #86 (time loop, done), #88 (homecoming: Sol, landing, credits), #87 (prologue: moon mission) and #89 (lore). The flight home from the LMC is the finale with the Rift chase (#81); still legacy until their issues land: the homecoming result screen instead of the Earth/Moon approach and landing (#88), the intro cinematic in a player's first loop instead of the prologue (#87), Ark instead of the home ship (#49), pirates (#51), Credits/Stardust names (#47). Energy Cells are gone (#78: Exotic Matter, item id `exotic`).
- Design + glossary (DE design term / EN UI term / code name) + names: `Assets/Design/DESIGN.md` "Gameplan: The Journey Home". Old code names stay until the issue that migrates a system renames it; new code uses the glossary names (`GalaxyDef`, `HomeEta`, `AlertLevel`, `Salvage`, `ExoticMatter`, `Rift`, `Memories` ...). UI language stays English.
User speaks German – answer in German.

## Layout (`Assets/_Project`)
- `Scripts/<Module>` with one asmdef each. Dependency order: Core ← Data ← Combat/Inventory/Planet ← Ship ← Player ← AI/World ← Progression/UI; Networking separate.
- `Editor/ContentBuilder.cs` (materials, all ScriptableObject data, balance values), `PrefabBuilder.cs` (all procedural meshes + prefabs + network prefab list), `SceneBuilder.cs` (scene `Scenes/Voidward.unity`, lighting, volume, project settings), `PlanetBuilder.cs` (planet presets `Data/Planets`, planet/ocean materials, detail textures, scene `Scenes/PlanetPreview.unity`), `BuildMenu.cs`.
- `Shaders/`: VW_ToonFlat (main lit), VW_Planet (triplanar terrain, elevation/slope/region ramp, planet-centered via `_PlanetCenter`), VW_Ocean (depth/opaque-texture water), VW_NebulaSkybox, VW_Atmosphere (depth-based ray-marched scattering shell, Cull Front + ZTest Always), VW_Clouds (procedural cloud shell), VW_Collapse, VW_Unlit, VW_AdditiveParticle, VW_Glass.
- **All content is generated.** Change the builder code, then run menu `Voidward/Build All Content`. Manual edits to generated prefabs/scene/data are overwritten.

## Architecture
- Session: `SessionManager` (host/join/transport switch, Steam → UTP fallback), `TransportConfig` (CLI: `-transport=utp|steam -autohost -autojoin=IP -autostart -players=N`).
- `DirectorSpawner` spawns the GameDirector prefab (`RunManager` + `CombatNet`) on `SessionManager.ServerStarted`.
- Journey structure (#46): `GalaxyDef` (5 assets, `ContentBuilder.BuildGalaxies`: route, distance, biome pool, enemy mix, `EnemyTier`/`LootTier`, palette, `DriveTier` for #73) -> `GalaxyGenerator.Generate(runSeed, galaxy)` = deterministic `GalaxyPlan` with 4-6 `StarSystem`s (`SystemKind`: Planetary, AsteroidField, Anomaly, Enclave (exactly one, Warden + hoard), Nomads (trader station), Void; system 0 = arrival, galaxy 1 system 0 = "Wormhole Exit" with station). `SystemLayout.Build(seed, galaxy, kind, station)` = the system corridor (planets, fields, wrecks, boss pos). Clients regenerate everything from the synced `RunSeed`/`GalaxyIndex`/`SystemIndex` (`RunManager.Plan`, `CurrentSystem`).
- `RunManager`: run lifecycle (start / continue / end), galaxy+system flow, warp (`RequestWarpServerRpc(target)` from a pilot, `WarpNextGalaxy` = -1 one-way, from galaxy 5 = the flight home (#81); countdown `WarpCountdown`; `ServerGoto(g, s)` for dev), ships/players, respawns, run clock (`RunTime`), stats, cheats (`ExecuteCheat(int)`). `SystemDirector` (plain server class): system content (`PopulatePlanet` POIs, wrecks, station), enemy spawning, events, Warden enclave. Revisited systems keep worlds/nodes/nests but spawn no crates (`VisitedMask`). Suspend save: `RunState` (versioned JSON, players by name, ships with modules/cargo) via `RunSave` (one slot `vw_run.json`), written on galaxy entry and `SessionManager.BeforeLeave` (host leaves/quits, also when stopping Play Mode), deleted by `EndRun`; lobby "Continue Run" -> `SessionManager.ContinueRun`. UI: `GalaxyMapView` (key M, `VwInput.Map`), HUD system meter + run clock.
- Warp drive (#78): `WarpDrive` (World, on the GameDirector) = the crew's shared drive until the home ship (#49): `Tiers` (NetworkList, tier per `DriveSlot` Core/Navigation/Cooling/Tank, 1-6) + `Exotic` (tank). Parts are items (`ItemKind.DriveComponent`, `ItemDef.Drive` -> `DriveComponentDef`, ids `drive_<core|nav|cooling|tank>_mk<1-6>`), swapped/loaded via `InstallFromInventoryServerRpc` / `LoadExoticServerRpc` near a ship. Balance in `WarpDriveDef` (core speeds, tank sizes, nav/cooling penalties) + `GalaxyDef.LegLength` (minutes with a balanced Mk I) / `LegFuel`; `DriveMath` = pure ETA/fuel math (`Minutes`, `Fuel`, `Eta`, `Delta`; stop `DriveMath.Home` = 6). Galaxy warps (`WarpNextGalaxy`, `WarpSkipGalaxy` = -2) check and burn Exotic Matter in `RunManager.FuelOk/ServerWarp`. UI: inventory tab *Warp Drive* (`EventBus.RaiseDrivePanelRequested`), galaxy map ETA/fuel/skip, HUD ETA line, cockpit via `GameState.HomeEta`. Save `RunState` v2 (`DriveTiers`, `Exotic`; v1 loads as Mk I).
- Flown galaxy warp (#79): `WarpFlight` (World, on the GameDirector): `RunManager.ServerWarp` to a galaxy stop -> `BeginWarpFlight` (director cleared) -> `WarpFlight.ServerBegin(from, to, lead)` -> ... -> `ServerArrive` -> `RunManager.ServerArrive(stop)` (`WarpTo` or the homecoming). Floating origin: ships stay near x = 0 (`WarpBubble.Axis` = +X), the corridor streams past; route length = model minutes / build factor / `BalancedFactor` x full-throttle speed (`VisualSpeed` per core tier), so a flight at the nav's safe speed in fields and full speed elsewhere takes `DriveMath.Minutes`. `WarpRoute` (pure, deterministic per flight seed, obstacles generated per 1 km chunk, id = chunk * 1024 + i): legs, zones (`WarpZone` ExitHalo/Void/ArrivalHalo, 12 % halos per leg), `WarpHazard` (Rock, Debris, Comet, Rift, GravityWell, StrayRock), 3 `WarpSignal`s per leg, `PatrolIn(chunk)`. Server state as NetworkVariables (Progress, Throttle, Heat, Cruise, Stalled, Overheated, Lead, Hazard, DroppedOut, DropSignal, ResumeCountdown, VisitedSignals, `Destroyed` list); fuel burns along the route (a mid-flight suspend save refunds it, the crew continues before the warp). `WarpBubble` (Core, static) carries the local state to Ship/Player: `ShipFlight.WarpStep` (lead: nose/strafe -> lateral velocity, cone 35 deg, corridor walls, `WarpBubble.Pull`; others: formation slot `WarpBubble.FormationOffset`), `ShipSeat.TickPilot` feeds W/S, X, C, G (`VwInput.Cruise/DropOut`), `PlayerPawn` FOV boost. `WarpCorridorView` (client, every peer): obstacle GameObjects inside the scanner range (`ScanRange` = nav fraction x speed x 2.6 s), `WarpObstacleProxy` trigger colliders for shots (like `AsteroidRock`), impact detection for every ship the peer simulates (`ShipFlight.IsSimulating`) -> `ReportImpactServerRpc`, gravity well pull, signal beacon, gas cloud, speed streaks. Sky: `SystemVisuals` swings the destination galaxy ahead and grows it with the progress. Signal sites spawn through `SystemDirector` (`SpawnWreckSite`, `SpawnRoguePlanet`, `TrackedCount`/`TakeTracked`). HUD: route meter + zone, throttle/heat/ETA/Exotic/cruise/signal line, centre warnings, ship card speed = warp throttle.
- Flight home + the Rift (#81): the galaxy warp 5 -> `DriveMath.Home` (`WarpFlight.IsFinale`, ~5 min with the Home Drive, LMC `LegLength` 1200 / speed 240). `RiftStart` (NetworkVariable, route m) = `FinaleSeconds` (300 s) of planned flight before the end, walked back over the real zones (`FinaleStartOf`; 0 with the Home Drive, the last ~5 min with weaker drives); `WarpRoute(finaleStart)` makes that stretch denser (void: stray rocks, rift walls, comets, wells), drops signals in/near it and the arrival welcome party. Server: `ServerRift` wakes the Rift at `RiftStart` with a 40 s lead, moves it at 0.8 -> 1.02 x the build's planned speed at the Rift's own position (`PlannedSpeedAt`: fields = nav fraction, void = sustain, so weak drives are not unfair in halos) -> `RiftGap`/`RiftSpeed` NetworkVariables; close (< `RiftCloseSeconds` 12 s) = warning + extra heat; at 55 % of the chase `ServerWardenWave` (tough interceptors of the last galaxy, they interdict); drop-outs are blocked while it chases; gap <= 0 -> `RunManager.ServerRiftCaught` (the time loop, #86). Arrival -> `ServerArrive(Home)` -> homecoming result (placeholder for the Sol approach, #74). Client: `WarpCorridorView.UpdateRift` = VW_Collapse maw (`ContentCatalog.CollapseMaterial`) + halo ring + tendrils behind the bubble, distance/size by `RiftSeconds`, violet pulse/shake + violet streaks when close; HUD rift pip on the route meter, "THE RIFT n s BEHIND" line, "THE RIFT IS CLOSING IN" centre warning, objective "THE FLIGHT HOME".
- System cruise + hops (#80): `ShipFlight` cruise (authority of a piloted ship): hold C (`ShipSeat` -> `SetCruiseInput`) for `CruiseSpool` 2 s, then `DriveMath.CruiseSpeed` per core tier (`WarpDriveDef.CruiseSpeed` 1-3 km/s, `WarpBubble.CoreTier` written by `WarpDrive`), owner-written `CruiseNet` (`CruiseMode`). Ends: X/S/C, a hull hit (`OnHullHit` = interdiction, blocks 3 s), engaged enemies within `CombatLockRange` (`Threat.EngagedNear`), a sphere cast ahead (collision alert), and towards a planet the closing speed eases down to normal flight at `GravitySource.CruiseRadius` (gravity field, at least radius + 1 km; `CruiseClearance`). Gravity + combat lock also gate warps (`RunManager.WarpLockOk` on request and at countdown end). System warps are flown hops: `WarpFlight.ServerBeginHop` (`TargetSystem` >= 0, `IsHop`), `WarpRoute(hop: true)` = one leg, 20 % system outskirts at each end with 40 % rock density, no signals/welcome party, `ZoneName`; length from `DriveMath.HopMinutes` (`WarpDriveDef.HopMinutes` 1.5 x factor / speed^0.35), no Exotic Matter; arrival `RunManager.ServerArriveSystem` -> system edge. Interdiction in any warp: engaged enemies within `WarpFlight.InterdictRange` of the lead ship or enemy hits on its hull stop the bubble (`[Warp] interdicted`). Normal flight: module thrust/top speed capped at `ShipCore.NormalFlightCap` (+30 %).
- Time loop (#86): every run is a loop; `RunManager.Loop` (NetworkVariable, the host's `Meta.Loops` + 1, in `RunState` v3 with the logbook). Story texts are data: `StoryDef` (`ContentCatalog.Story`, `ContentBuilder.BuildStory`: deja-vu radio per loop, radio echoes per galaxy (6 = flight home) with `MinLoop`, crew logbook templates with {loop}/{galaxy}/{eta}/{part}/{ship}, reset banners). Crew logbook: `RunManager.ServerLog(template)` at milestones (loop start, galaxy reached, Warden enclave cleared, better drive part installed (`WarpDrive`), Ark lost, flight home, death, homecoming) -> `EventBus.LogbookEntry` (HUD ticker) + `RunSummary.Log`. Death (crew lost / caught by the Rift) = `EndRun` -> `GamePhase.GameOver` -> every client plays `LoopView.Collapse` (unscaled, `Time.timeScale` slow-mo, violet iris + shutters closing to black, "THE LOOP RESETS") -> results screen = the loop's logbook (cause, galaxy, core, Home ETA + best, log) -> host "New Loop" (`NewLoopServerRpc` -> `ServerNewLoop` = `ClearRun` + `ServerStartRun`) or Lobby. Start: a player's first loop (`Meta.Loops == 0`) gets the intro cinematic, later loops the short deja-vu (`LoopView.DejaVu`: violet flash + distorted radio, read 0.6 s after the phase change because clients get `Loop` later); echoes play on entering a galaxy this player has reached before (`Meta.Data.BestSector`). Meta: `Meta.Loops` (= `Runs`), `MetaSave.BestEtaMinutes`.
- `GameState` (Core/Contracts.cs): static shared client state (UIOpen, Phase, SectorIndex, Objective…).
- Authority: pawns + ships use owner-authoritative NetworkTransform; pilot seat transfers ship ownership. Projectiles are server-simulated in `CombatNet` with cosmetic client copies. Planets/asteroids are seed-synced, not replicated.
- Planets (#17, #21): radius 1.0-1.9 km (`SystemLayout.Min/MaxPlanetRadius`, 0-3 per system depending on its kind, alternating corridor sides). `BiomeDef.Shape` -> `PlanetShapeDef` (noise layers, landforms = volcano/mesa/spire/basin/dome, canyon network incl. river/lava channels, craters, ocean, region colors, sites, atmosphere, clouds, decor style, particles, weather). `PlanetTerrain` = deterministic, thread-safe height field (single source of truth for chunks, colliders, decor, sites, `PlanetBody` queries, `Raycast`). `PlanetVisuals` = 6 quadtrees of chunks (`PlanetMesh.BuildChunk` on worker threads, tangent-adjusted cube mapping, skirts, horizon culling), collider tiles streamed around `TerrainAnchor`s (pawn + ship prefabs), per-chunk props (`PlanetDecor`), set pieces (`PlanetLandmarks`), ocean/atmosphere/cloud shells. `PlanetAmbience` (client) = particles, weather, haze/ambient override, wind audio. `PlanetBody.SiteKinds` (deterministic) drive POI clusters in `SystemDirector.PopulatePlanet` and HUD site markers. `GravitySource.GroundRadiusAt` makes altitude checks terrain-aware. Far terrain has no colliders: use `PlanetBody.Raycast/SurfaceWorldPoint` or `GravitySource.GroundPoint`, not Physics, for spawn/placement. Dev preview: menu `Voidward/Open Planet Preview`, then Play. Planet look (#70): VW_Planet = soft wrap lighting (no toon bands), procedural macro noise (never fades), cavity AO from chunk UV1.x (mesh Laplacian), cliff strata; VW_Ocean = depth absorption, reflects the planet's own sky (`_SkyColor`/`_HorizonColor`), distance-dependent GGX glint, shore foam, `PlanetShapeDef.Lava` switches to the crust/crack lava mode; VW_Clouds = soft edges + sun-offset self shadow.
- Seats don't reparent: the pawn follows `ShipSeat.SeatOf` in LateUpdate; seated capsules are disabled on all peers.
- Floating origin: each system is generated around the origin; on warp, ships and pawns are rebased via `NetTeleport` (sent to the transform owner). `SystemVisuals` (client) builds asteroids, galaxy palette, music and the journey sky (destination galaxy + Milky Way growing per galaxy).
- UI is fully code-built (`UIKit`, `UIRoot`, `MenuScreens`, `HudView`, `InventoryView`, `TradeView`). Namespace `Voidward.UI` has enum `Screen` → write `UnityEngine.Screen` explicitly.
- Meta progression: `Progression/Meta.cs` (Stardust, perks, local save; `Meta.ResetAll()`).

## Conventions / gotchas (learned the hard way)
- One MonoBehaviour/NetworkBehaviour per file, file name = class name (otherwise "missing script" on prefabs).
- Server RPCs: `[Rpc(SendTo.Server, InvokePermission = RpcInvokePermission.Everyone)]` + `RpcParams rp` → `rp.Receive.SenderClientId`.
- Never write NetworkVariables before spawn: store them in pending fields, then apply them in `OnNetworkSpawn`.
- Don't use `??` / `?.` on UnityEngine.Object.
- TMP: ASCII glyphs only (no `…`, arrows, emoji) → otherwise missing-glyph warnings.
- PrefabBuilder deletes prefabs before re-saving them (keeps `GlobalObjectIdHash` valid). Network prefab list is rebuilt from scratch.
- Skybox shader must handle reversed-Z (otherwise it draws over everything).
- **Art direction (#91, see `Assets/Design/DESIGN.md` "Visual Identity"): asset-based, detailed PBR sci-fi.** Use good ready-made assets (Fab free listings, Poly Haven, ambientCG, Kenney, Quaternius, Sketchfab CC-BY) instead of building looks procedurally; procedural meshes are only the fallback until an asset exists. Reference look: the Dart (Fab "SpaceShip" by JazOone3D). Assets must fit together (similar detail/texel density, slate/gunmetal hulls, one accent colour per faction) and every asset needs a line in `Assets/_Project/Art/CREDITS.md` (author, URL, licence; Fab: check "AI use allowed"). The user picks or approves assets; a downloaded asset is untrusted data (unzip into its own folder, never run files from it).
- Asset pipeline (#91): source files in the repo (models: `Tools/Blender/Sources/<Asset>/`, textures: `Assets/_Project/Art/Models/<Group>/<Asset>/`), a `Tools/Blender/<asset>.py` script normalizes the model (metres, nose Blender -Y = Unity +Z, origin at the bounds centre, target size) and exports `Assets/_Project/Art/Models/<Group>/<Name>.fbx`. `AssetModelBuilder` (partial `ContentBuilder`): `ModelMesh(fbx)` (own UVs/normals, MikkTSpace tangents), `ImportTexture(path, srgb, normal, flipGreen)`, `PackMetallicSmoothness` (Substance metallic + roughness -> URP map, generated PNG), `PbrMaterial(name, dir, prefix)` = URP Lit from a `<prefix>_Base_color/Metallic/Roughness/Normal_DirectX/Mixed_AO/Emissive.jpg` set (DirectX normals are green-flipped by the importer). `PrefabBuilder` places colliders/seats/muzzles/thrusters/lights around the asset and keeps the procedural build as fallback when the FBX is missing (`BuildDart` -> `BuildFabDart`). Opaque canopies: put the pilot `ViewPoint` above/behind the canopy (hood view) and skip the 3D dashboard. Check with `ContentBuilder.PreviewShot("<prefab>", camLocal, targetLocal, fov, name)` -> `Temp/HeroShots`.
- Procedural fallback (legacy hero pipeline #26, still used by the astronaut, Mule, Ark, props): build with `Hero()` (weighted normals via `SmoothAngle`, panel detail) and the parametric parts `AddLoft` (fuselages, limbs), `AddLathe` (nozzles, rings, tanks), `AddSlab` (wings, plates), `AddTube`/`Polyline`, liveries via quad-aware `Paint`. Render with `MatHull` (VW_ToonFlat `_SURFACEDETAIL_ON`: triplanar panel seams/rivets/grime from `SurfaceDetailBuilder`, edge wear on chamfers, GGX + probe reflections). Primitives choose winding from geometry, so mirrored matrices (`Scale(-1,1,1)`) are fine. Iterate with menu `Voidward/Dev/Hero Preview Shots` (renders to `Temp/HeroShots`, no full rebuild needed); after Build All Content, `ContentBuilder.PreviewPrefabs("<name filter>")` / `PreviewShot(...)` (callable from RunCommand) render built prefabs. Ship exhaust and projectiles = `VW_Plume` (additive fresnel). Soot/burns: `MeshBuilder.Weather`; contact shading: `Grade`. Planet decor, landmarks, asteroids and the menu ground use `VW_Terrain` with a rock detail mask (enable via `MeshBuilder.Panel = 1`). Per-sector color grading lives in `PaletteDef` (runtime volume in `SectorVisuals`).
- Editor ↔ release build = "NetworkConfig mismatch". Use a Development build (`Voidward/Build/macOS (Development)` or `Windows (x64, Development)`) or MPPM.
- Owning a ship in its spawn frame breaks positioning for remote clients → `RunManager.SeatLater` delays it by 0.6 s.

## Issue workflow (mandatory)
Repo: `Weofi/Space-Beyond-Infinity`, default branch `main`. When the user hands over an issue:
1. Read the issue (incl. images/mockups) via `gh issue view <nr> --comments`.
2. `git checkout main && git pull`, then create a dedicated branch `issue-<nr>-<short-slug>` (never work on `main`).
3. Push the branch early and open a **draft PR** against `main` with `Closes #<nr>` in the body (check for a PR template first).
4. Implement on that branch with small, descriptive commits (`#<nr>: ...`), push regularly.
5. When done: compile check + test per the "Testing playbook" (cheapest level first, not a full run), update the PR description (changes, test notes, screenshots), mark it ready for review.
6. If everything works and the issue is fully done: merge the PR into `main` yourself (user-approved), then `git checkout main && git pull`. If anything is broken or open, don't merge; report back instead.
One issue = one branch = one PR. Don't mix issues.

## Agent workflow (Unity MCP)
- Don't edit C# while Unity is in Play Mode (a domain reload breaks statics).
- Compile check: read `Logs/Editor.log` after the last "Requested script compilation" and grep `): error CS`.
- `Unity_RunCommand` returns "Unity not detected" while compiling/reloading → just retry. System.Reflection is not allowed there.
- Run menu items (`Voidward/Build All Content`, `Voidward/Build/...`) via ManageMenuItem, not RunCommand. Exception: dev builds, see the testing playbook.
- Never call `AssetDatabase.Refresh`/`ImportAsset` in Play Mode: it can trigger a script recompile + domain reload that breaks the session (UIRoot NREs). Shader tweaks: exit Play Mode first, or check them in Edit Mode (render a quad with the material).
- Target: zero console errors/warnings from Voidward code. Known foreign noise: AI Inference tensor warnings, PreviewRenderUtility leak.
- Unity skills (`.agents/skills`, from `Unity-Technologies/skills`, lock: `skills-lock.json`): use them as domain knowledge only. Implement their recommendations in the builder code (`ContentBuilder`/`PrefabBuilder`/`SceneBuilder`) or in runtime code, never as direct edits to generated scenes/prefabs/assets. Update: `npx skills update -p`.

## Testing playbook (dev harness, #65)
Goal: test the situation, not a whole run, and keep tool output small. Harness = `Scripts/Dev` (`Voidward.Dev`, editor + development builds only).
- **Pick the cheapest level**: shader/particle look → Edit Mode (render a quad / `DevShots.Shot(name, pose)` works outside Play Mode) or the Lab; gameplay in context → `QuickStart` + a few shots; MP only when RPCs/NetworkVariables/authority changed.
- **Start** (one RunCommand line from Edit Mode, survives the domain reload): `Voidward.Dev.DevTest.Play(Voidward.Dev.DevScenario.Lab)`; then `bash Tools/Dev/dev-wait.sh quickstart` (no sleeps). Scenarios: `Space` (pilot seat), `Planet` (on foot, sunlit dry ground, blaster, god mode), `Lab` (5 test walls Metal/Rock/Dirt/Organic/Shield next to the trader station, same on every peer), `Galaxy` (pilot seat, galaxy map open). Already playing: `DevTest.QuickStart(...)`. Humans: menu `Voidward/Dev/Play: ...`.
- **Act**: `DevTest.Fire(kind, from, to)` (server, dmg 0), `Hitscan(from, to)`, `PawnShoot(target, rifle)` + `GroundAhead(dist, side)`, `SpawnEnemy(kind, pos, lookAt)`, `Teleport`, `God`, `ClearDecals`, `DecalCount`; damage taken: `HurtPawn(amount, fromDir)` / `HurtShip(amount, fromDir)` (server hit from a world direction, ignores god mode; ship = shield first), `SetVitals(health01, shield01)`; lab: `LabTargets[i]`, `LabGun(i)`, `LabCam`, `LabClose(i)`.
- **Journey (#46)**: `GotoGalaxy(g, s)` / `GotoSystem(s)` (server, instant warp, logs `[Dev] end goto <SystemInfo>`), `SystemInfo` (galaxy, system, kind, planets, visited, run time), `GalaxySystems` ("0:Planetary 1:Nomads ..."), `SaveRun()` / `HasRunSave`; continue test: `ServerReturnToLobby()` then `SessionManager.Instance.ContinueRun()`. Ending a run (`EndRun`) records it in the real meta save: `BackupMeta()` first, `RestoreMeta()` after.
- **Warp drive (#78)**: `SetDrive(tier)` / `SetDrive(core, nav, cooling, tank)`, `SetFuel(x)` (server), `DriveInfo` ("core 2 nav 2 cool 1 tank 1 | exotic 4/12 | next 10:00 (8) skip ... home ... | factor 1.08"); warp with `RunManager.Instance.ServerWarp(RunManager.WarpNextGalaxy / WarpSkipGalaxy)` (aborts without fuel unless god mode). MP: with `-devshots` the client also logs `[Dev] client<id>_<t> galaxy G drive <DriveInfo>` (compare with the host). Pure ETA numbers need no Play Mode: `DriveMath.Compute(ContentCatalog.Instance.WarpDrive, ...)` in Edit Mode.
- **Warp flight (#79)**: scenario `Warp` (lead pilot in a flown warp M33 -> M31, Mk II, cruising 60 %). `StartWarp(target)` (server, skips countdown, loads the fuel it needs; logs `[Dev] end warp <WarpInfo>`), `WarpInfo` ("1 -> 2 | 34.2/210.0 km 16% GALAXY HALO | throttle .. heat .. cruise .. stall .. hot .. | lead .. hazard .. | out .. | exotic .. | scan .. | destroyed .."), `WarpSegment(WarpZone)`, `WarpAhead(WarpHazard, dist)` (next obstacle of a kind `dist` m ahead), `WarpSignalAhead(dist)`, `WarpProgress(0..1)`, `SetThrottle(t, cruise)`, `WarpLeadTo(y, z)` (lead ship to a lateral lane), `WarpDropOut()` (server, as [G]: drop out at the signal in range / start the 5 s resume countdown; works without editor focus), `WarpPatrolAhead()` (bubble just before the next interceptor patrol chunk; they spawn once it moves). Slingshot test: hold the lead on a lane 2x the well radius beside a gravity well with a `Sequence` step calling `WarpLeadTo` + `SetThrottle` each frame (unpiloted, the well's pull drags the ship into the core). Server log: `[Warp] begin/impact/slingshot/arrived`. A route is pure: `new WarpRoute(seed, from, to, length)` works in Edit Mode. MP: the client log line also carries `| warp <WarpInfo>`.

## Cross-platform (Mac + Windows)
- Same Unity version on both machines (`ProjectSettings/ProjectVersion.txt`). Line endings are pinned to LF via `.gitattributes`.
- Before switching machines: commit + push. On the other machine: `git pull` first, then open Unity.
- `.mcp.json` is git-ignored (machine-specific Unity relay path); each machine keeps its own.
- GitHub: use the GitHub CLI (`gh`, logged in via `gh auth login --web`) for issues, PRs and merges. No GitHub MCP server (its OAuth needs dynamic client registration, which Claude Code can't do with GitHub). On Windows, `gh` lives at `C:\Program Files\GitHub CLI\gh.exe` (call it by full path if PATH isn't refreshed yet).
- Blender: Windows `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`; Mac `/Applications/Blender.app/Contents/MacOS/Blender` (install the same 5.2 version there).

## Blender (asset scripts)
- When to use: normalizing imported assets (#91, e.g. `Tools/Blender/fab_spaceship.py`), and own models where no asset exists (organic forms, baked AO/normal maps). Procedural C# is only the fallback.
- Keep it reproducible: Blender content is a Python script in the repo (e.g. `Tools/Blender/<asset>.py`), never a hand-edited `.blend` as the only source. Exported FBX goes to `Assets/_Project/Art/Models/` and is committed (Unity must build without Blender); `PrefabBuilder` references it.
- Run headless: `blender -b --factory-startup -P script.py -- <args>`. In 5.2, FBX export applies modifiers via `use_mesh_modifiers=True` (not `apply_modifiers`). Unity is Y-up / Blender Z-up: export with `axis_forward='-Z', axis_up='Y'` and check scale (1 unit = 1 m).
- Shared helpers: `Tools/Blender/vw_blender.py` (skin skeletons, warp, displacement, Cycles AO bake, export). Vertex data contract: colour attribute `Col` (sRGB) = base colour, UV map `surf` = (gloss, glow), UV map `detail` = (metal, baked AO); model faces Blender -Y (becomes Unity +Z; Blender +X becomes Unity -X). `PrefabBuilder.ImportedMesh` converts such an FBX to the MeshBuilder layout (C# meshes stay as fallback). Example: `Tools/Blender/aliens.py`.
- After a first open/reimport on a machine, check `git status` before committing: reimport noise (package `.meta` files, emptied `m_List` in `UniversalRenderPipelineGlobalSettings.asset`) must not be committed.
