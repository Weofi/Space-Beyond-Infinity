## Gameplan (2026-10-13, from issue #72; design reference since 2026-10-17: `Assets/Design/DESIGN.md`)
**Direction 2026-10-17 (DESIGN.md "Gameplan"):** one continuous co-op journey, no roguelite runs and no time loop. Progress = upgrading the ships and the warp drive. Open world: the scanner shows every site (ore to ruins) and the Nostos' board computer highlights what is interesting or needed, without missions; flying there, landing, disembarking, harvesting and carrying the loot back are played in the world. A failed landing costs what the landing party carried, the landed ship stays as a salvageable wreck (#132). The Rift (#81) is dropped too; its code is removed in #132. Progression has two layers: the players' own crew ships (classes Dart -> heavy fighter -> multi-crew frigate, no freighters, #113) and the Nostos as shared base, scanner platform and jump ship whose upgrades (warp drive first) open further areas. Where the text below describes the loop, that is the current code, not the target.
The game is now a **journey home**: a moon mission (*SELENE-4*) on its return flight to Earth (the family watches it live on the news, #109) is swallowed by an anomaly/wormhole, the crew wakes in M33 and flies through 5 Local Group galaxies (M33 -> M31 -> NGC 6822 -> Leo I -> LMC) home to Sol, upgrading the **warp drive** (Mk I-V, Home Drive) to shrink the **Home ETA**. Travel = flown warp flights (#73). Death = time loop back to M33 with meta kept (#74, #86); **planned (2026-10-17): #132 replaces it with a system loop** (down/revive, solo emergency cryo, crew wipe = the current system loops back to its arrival checkpoint, same layout, rerolled enemies/loot). Gameplay core planned in #128 (galaxy missions: signals, orbital scan, coordinate fragments -> drive core), #129 (expeditions: drill, salvage, ruin, per-planet alert level), #130 (every pilot flies their own ship inside the warp bubble, multi-seat = gunner/engineer), #131 (drive variants with trade-offs). Enemies: nature + aliens only (no pirates); Wardens = alien guardian species (#42). Collapse -> the Rift (finale only). Credits -> Salvage (`NetInventory.Salvage`), Stardust -> Memory fragments (`Meta.Data.Memories`), done in #112.
- **Gameplay decisions follow `Assets/Design/DESIGN.md` "Gameplan: The Journey Home" and the open issues in roadmap #53, not the legacy code** (#72, the original gameplan issue, is closed; "part of #72" in issues is history). #46 (run structure: 5 galaxies, systems, galaxy map, suspend save; gates/Collapse removed) is in. #73 is split into #78 (crew warp drive), #79 (flown warp), #80 (cruise, hops) and #81 (finale), all done. #74 is split into #86 (time loop, done), #87 (prologue: playable return flight from the Moon, anomaly, waking in M33), #109 (story intro: family watching the news, TV -> cockpit, "SIGNAL LOST"), #88 (homecoming: Sol, landing on Earth, closing news scene, credits), #132 (system loop) and #89 (lore), in that order (sub-issues of #74). #49 is now only the home ship *Nostos* (the SELENE-4 mission ship, built from the Ark); small ships moved to #113. #108 (done) replaced the warp button/countdown: every hop and galaxy warp starts seamlessly by flying out of a jump zone at the system edge (Galactic Rim + skip zone only in a galaxy's outermost system). ## Layout (`Assets/_Project`)
- `Scripts/<Module>` with one asmdef each. Dependency order: Core ← Data ← Combat/Inventory/Planet ← Ship ← Player ← AI/World ← Progression/UI; Networking separate.
- `Editor/ContentBuilder.cs` (materials, all ScriptableObject data, balance values), `PrefabBuilder.cs` (all procedural meshes + prefabs + network prefab list), `SceneBuilder.cs` (scene `Scenes/Voidward.unity`, lighting, volume, project settings), `PlanetBuilder.cs` (planet presets `Data/Planets`, planet/ocean materials, detail textures, scene `Scenes/PlanetPreview.unity`), `BuildMenu.cs`.
- `Shaders/`: VW_ToonFlat (main lit), VW_Planet (triplanar terrain, elevation/slope/region ramp, planet-centered via `_PlanetCenter`), VW_Ocean (depth/opaque-texture water), VW_NebulaSkybox, VW_Atmosphere (depth-based ray-marched scattering shell, Cull Front + ZTest Always), VW_Clouds (procedural cloud shell), VW_Collapse, VW_Unlit, VW_AdditiveParticle, VW_Glass.
- **All content is generated.** Change the builder code, then run menu `Voidward/Build All Content`. Manual edits to generated prefabs/scene/data are overwritten.

## Architecture
- Session: `SessionManager` (host/join/transport switch, Steam → UTP fallback), `TransportConfig` (CLI: `-transport=utp|steam -autohost -autojoin=IP -autostart -players=N`).
- `DirectorSpawner` spawns the GameDirector prefab (`RunManager` + `CombatNet`) on `SessionManager.ServerStarted`.
- Journey structure (#46): `GalaxyDef` (5 assets, `ContentBuilder.BuildGalaxies`: route, distance, biome pool, enemy mix, `EnemyTier`/`LootTier`, palette, `DriveTier` for #73) -> `GalaxyGenerator.Generate(runSeed, galaxy)` = deterministic `GalaxyPlan` with 4-6 `StarSystem`s (`SystemKind`: Planetary, AsteroidField, Anomaly, Enclave (exactly one, Warden + hoard), Nomads (trader station), Void; system 0 = arrival, galaxy 1 system 0 = "Wormhole Exit" with station). `SystemLayout.Build(seed, galaxy, kind, station)` = the system corridor (planets, fields, wrecks, boss pos). Clients regenerate everything from the synced `RunSeed`/`GalaxyIndex`/`SystemIndex` (`RunManager.Plan`, `CurrentSystem`).
- `RunManager`: run lifecycle (start / continue / end), galaxy+system flow, warp (no button since #108: `ServerJump(target, lead)` from a jump zone, `ServerWarp(target)` for cheats/dev; `WarpNextGalaxy` = -1 one-way, from galaxy 5 = the flight home (#81); `ServerGoto(g, s)` for dev), ships/players, respawns, run clock (`RunTime`), stats, cheats (`ExecuteCheat(int)`). `SystemDirector` (plain server class): system content (`PopulatePlanet` POIs, wrecks, station), enemy spawning, events, Warden enclave. Revisited systems keep worlds/nodes/nests but spawn no crates (`VisitedMask`). Suspend save: `RunState` (versioned JSON, players by name, ships with modules/cargo) via `RunSave` (one slot `vw_run.json`), written on galaxy entry and `SessionManager.BeforeLeave` (host leaves/quits, also when stopping Play Mode), deleted by `EndRun`; lobby "Continue Run" -> `SessionManager.ContinueRun`. UI: `GalaxyMapView` (key M, `VwInput.Map`), HUD system meter + run clock.
- Warp drive (#78): `WarpDrive` (World, on the GameDirector; since #49 the Nostos's drive: worked on aboard it, `AtShip`): `Tiers` (NetworkList, tier per `DriveSlot` Core/Navigation/Cooling/Tank, 1-6) + `Exotic` (tank). Parts are items (`ItemKind.DriveComponent`, `ItemDef.Drive` -> `DriveComponentDef`, ids `drive_<core|nav|cooling|tank>_mk<1-6>`), swapped/loaded via `InstallFromInventoryServerRpc` / `LoadExoticServerRpc` near a ship. Balance in `WarpDriveDef` (core speeds, tank sizes, nav/cooling penalties) + `GalaxyDef.LegLength` (minutes with a balanced Mk I) / `LegFuel`; `DriveMath` = pure ETA/fuel math (`Minutes`, `Fuel`, `Eta`, `Delta`; stop `DriveMath.Home` = 6). Galaxy warps (`WarpNextGalaxy`, `WarpSkipGalaxy` = -2) check and burn Exotic Matter in `RunManager.FuelOk/ServerWarp`. UI: inventory tab *Warp Drive* (`EventBus.RaiseDrivePanelRequested`), galaxy map ETA/fuel/skip, HUD ETA line, cockpit via `GameState.HomeEta`. Save `RunState` v2 (`DriveTiers`, `Exotic`; v1 loads as Mk I).
- Flown galaxy warp (#79): `WarpFlight` (World, on the GameDirector): `RunManager.ServerWarp` to a galaxy stop -> `BeginWarpFlight` (director cleared) -> `WarpFlight.ServerBegin(from, to, lead)` -> ... -> `ServerArrive` -> `RunManager.ServerArrive(stop)` (`WarpTo` or the homecoming). Floating origin: ships stay near x = 0 (`WarpBubble.Axis` = +X), the corridor streams past; route length = model minutes / build factor / `BalancedFactor` x full-throttle speed (`VisualSpeed` per core tier), so a flight at the nav's safe speed in fields and full speed elsewhere takes `DriveMath.Minutes`. `WarpRoute` (pure, deterministic per flight seed, obstacles generated per 1 km chunk, id = chunk * 1024 + i): legs, zones (`WarpZone` ExitHalo/Void/ArrivalHalo, 12 % halos per leg), `WarpHazard` (Rock, Debris, Comet, Rift, GravityWell, StrayRock), 3 `WarpSignal`s per leg, `PatrolIn(chunk)`. Server state as NetworkVariables (Progress, Throttle, Heat, Cruise, Stalled, Overheated, Lead, Hazard, DroppedOut, DropSignal, ResumeCountdown, VisitedSignals, `Destroyed` list); fuel burns along the route (a mid-flight suspend save refunds it, the crew continues before the warp). `WarpBubble` (Core, static) carries the local state to Ship/Player: `ShipFlight.WarpStep` (lead: nose/strafe -> lateral velocity, cone 35 deg, corridor walls, `WarpBubble.Pull`; others: formation slot `WarpBubble.FormationOffset`), `ShipSeat.TickPilot` feeds W/S, X, C, G (`VwInput.Cruise/DropOut`), `PlayerPawn` FOV boost. `WarpCorridorView` (client, every peer): obstacle GameObjects inside the scanner range (`ScanRange` = nav fraction x speed x 2.6 s), `WarpObstacleProxy` trigger colliders for shots (like `AsteroidRock`), impact detection for every ship the peer simulates (`ShipFlight.IsSimulating`) -> `ReportImpactServerRpc`, gravity well pull, signal beacon, gas cloud, speed streaks. Sky: `SystemVisuals` swings the destination galaxy ahead and grows it with the progress. Signal sites spawn through `SystemDirector` (`SpawnWreckSite`, `SpawnRoguePlanet`, `TrackedCount`/`TakeTracked`). HUD: route meter + zone, throttle/heat/ETA/Exotic/cruise/signal line, centre warnings, ship card speed = warp throttle.
- Flight home + the Rift (#81, **Rift dropped 2026-10-17, removed in #132**): the galaxy warp 5 -> `DriveMath.Home` (`WarpFlight.IsFinale`, ~5 min with the Home Drive, LMC `LegLength` 1200 / speed 240). `RiftStart` (NetworkVariable, route m) = `FinaleSeconds` (300 s) of planned flight before the end, walked back over the real zones (`FinaleStartOf`; 0 with the Home Drive, the last ~5 min with weaker drives); `WarpRoute(finaleStart)` makes that stretch denser (void: stray rocks, rift walls, comets, wells), drops signals in/near it and the arrival welcome party. Server: `ServerRift` wakes the Rift at `RiftStart` with a 40 s lead, moves it at 0.8 -> 1.02 x the build's planned speed at the Rift's own position (`PlannedSpeedAt`: fields = nav fraction, void = sustain, so weak drives are not unfair in halos) -> `RiftGap`/`RiftSpeed` NetworkVariables; close (< `RiftCloseSeconds` 12 s) = warning + extra heat; at 55 % of the chase `ServerWardenWave` (tough interceptors of the last galaxy, they interdict); drop-outs are blocked while it chases; gap <= 0 -> `RunManager.ServerRiftCaught` (the time loop, #86). Arrival -> `ServerArrive(Home)` -> homecoming result (placeholder for the Sol approach, #74). Client: `WarpCorridorView.UpdateRift` = VW_Collapse maw (`ContentCatalog.CollapseMaterial`) + halo ring + tendrils behind the bubble, distance/size by `RiftSeconds`, violet pulse/shake + violet streaks when close; HUD rift pip on the route meter, "THE RIFT n s BEHIND" line, "THE RIFT IS CLOSING IN" centre warning, objective "THE FLIGHT HOME".
- System cruise + hops (#80): `ShipFlight` cruise (authority of a piloted ship): hold C (`ShipSeat` -> `SetCruiseInput`) for `CruiseSpool` 2 s, then `DriveMath.CruiseSpeed` per core tier (`WarpDriveDef.CruiseSpeed` 1-3 km/s, `WarpBubble.CoreTier` written by `WarpDrive`), owner-written `CruiseNet` (`CruiseMode`). Ends: X/S/C, a hull hit (`OnHullHit` = interdiction, blocks 3 s), engaged enemies within `CombatLockRange` (`Threat.EngagedNear`), a sphere cast ahead (collision alert), and towards a planet the closing speed eases down to normal flight at `GravitySource.CruiseRadius` (gravity field, at least radius + 1 km; `CruiseClearance`). Gravity + combat lock also hold jump zones (`RunManager.JumpBlockFor`). System warps are flown hops: `WarpFlight.ServerBeginHop` (`TargetSystem` >= 0, `IsHop`), `WarpRoute(hop: true)` = one leg, 20 % system outskirts at each end with 40 % rock density, no signals/welcome party, `ZoneName`; length from `DriveMath.HopMinutes` (`WarpDriveDef.HopMinutes` 1.5 x factor / speed^0.35), no Exotic Matter; arrival `RunManager.ServerArriveSystem` -> system edge. Interdiction in any warp: engaged enemies within `WarpFlight.InterdictRange` of the lead ship or enemy hits on its hull stop the bubble (`[Warp] interdicted`). Normal flight: module thrust/top speed capped at `ShipCore.NormalFlightCap` (+30 %).
- Jump zones (#108): no warp button or countdown. `SystemLayout.AddJumpZones(plan, system)` (also in `GalaxyGenerator.Layout` and `SystemDirector.Enter`) puts `JumpZone`s (Core, `JumpZones` static: `Current`, `Blocks`, `CrewMissing`, `Entering`, `Veil`) on an ellipsoid around the corridor, pushed out until clear of every planet's gravity field: a hop zone to each neighbouring system (`GalaxyPlan` order, aimed like the map), and in the outermost system the Galactic Rim (`WarpNextGalaxy`, normal = `SystemVisuals.DestinationDir`; LMC: `JumpKind.Home` towards `MilkyWayDir`) plus the skip zone (`WarpSkipGalaxy`, beside it, further out). `WarpFlight.Jumps.cs` (partial): server packs a `JumpBlock` per zone into `JumpBlocks` (crew not aboard = a living pawn neither seated nor inside a `GravityVolume`; Exotic Matter/tank; combat/gravity lock via `RunManager.JumpBlockFor`); a piloted ship inside an open zone that crosses its plane cruising, or after `JumpZones.AlignSeconds` (3 s) nose outward, starts the entry (`EntryAt` = server time + `EnterSeconds` 2.6 s: FOV, entry speed lines in `WarpCorridorView`, veil) -> `RunManager.ServerJump` -> `BeginWarpFlight(seamless)` -> `WarpFlight.ServerRebaseIntoBubble` (every ship keeps its offset/attitude to the lead turned so the lead's nose = `WarpBubble.Axis`; ships > 450 m away get a formation slot; the bubble starts in warp cruise at ~nav/sustain x 0.8). End of the route: `ServerBeginExit` holds the flight `ExitSeconds` 0.8 s while the veil rises, then `RunManager.ServerArrive(System)(.., lead)` -> `RegroupOutOfWarp` (rigid transform to `SystemLayout.Arrival(fromSystem)`: inside the zone leading back, nose inward; galaxies: `StartPoint`) + `ShipFlight.ArriveFromWarpRpc` (owner, applied once the bubble state ended: piloted ships cruise in). The veil (`RebaseAt`, `VeilAt` curve, colour by `VeilKind`) is a full-screen image in `UIRoot`. Blocked zones: `ShipFlight.JumpZoneHold` (owner) dumps cruise and holds the ship at the plane. Visuals: `SystemVisuals.BuildJumpZones` (turning beacon ring + motes, additive dots, colour per `JumpKind`); HUD: zone markers with block reason, centre `JumpMessage` (ALIGNING n% / JUMP ZONE HOLDS - reason / WARP ENTRY); galaxy map = navigation only (hop lanes, zone list, galaxy warp ETA/fuel).
- Time loop (#86, **dropped 2026-10-17, still in the code until #132 removes it**): every run is a loop; `RunManager.Loop` (NetworkVariable, the host's `Meta.Loops` + 1, in `RunState` v3 with the logbook). ## Conventions / gotchas (learned the hard way)
- One MonoBehaviour/NetworkBehaviour per file, file name = class name (otherwise "missing script" on prefabs).
- Server RPCs: `[Rpc(SendTo.Server, InvokePermission = RpcInvokePermission.Everyone)]` + `RpcParams rp` → `rp.Receive.SenderClientId`.
- Never write NetworkVariables before spawn: store them in pending fields, then apply them in `OnNetworkSpawn`.
- Don't use `??` / `?.` on UnityEngine.Object.
- TMP: ASCII glyphs only (no `…`, arrows, emoji) → otherwise missing-glyph warnings.

## Issue workflow (mandatory)
Repo: `Weofi/Space-Beyond-Infinity`, default branch `main`. When the user hands over an issue:
1. Read the issue (incl. images/mockups) via `gh issue view <nr> --comments`.
2. `git checkout main && git pull`, then create a dedicated branch `issue-<nr>-<short-slug>` (never work on `main`).
3. Push the branch early and open a **draft PR** against `main` with `Closes #<nr>` in the body (check for a PR template first).
4. Implement on that branch with small, descriptive commits (`#<nr>: ...`), push regularly.
5. When done: compile check + test per the "Testing playbook" (cheapest level first, not a full run), update the PR description (changes, test notes, screenshots), mark it ready for review.
6. If everything works and the issue is fully done: merge the PR into `main` yourself (user-approved), then `git checkout main && git pull`. If anything is broken or open, don't merge; report back instead.
One issue = one branch = one PR. Don't mix issues.

## Art & assets (mandatory for all visual work, low-poly style #120)
Art direction since 2026-10-17: **low poly, flat-shaded, one shared palette** (variant A; reasons and comparison in #120 and `Docs/screenshots/lowpoly-audit/`). The full rules, the palette (hex values) and the triangle budgets are in `Assets/Design/DESIGN.md` "Visual Identity". **Priority (2026-10-17, #53): gameplay first.** New visual content (ships, enemies, stations, props, planets/terrain, skies, VFX, UI art) is built in this style right away, also when the issue does not mention art. Existing legacy content is not converted just because it is there: only when a task really changes that asset; otherwise it waits for its #120 issue (phase 7 of #53). Rules:
1. **Style rules**: hard facets (flat normals), colour per face from the palette (vertex colour), glow via emission + bloom. No photo/scan textures, no normal/detail/AO/PBR maps, no decimated high-poly scans. Material = `VW_ToonFlat` with `_FLATSHADING_ON` + `_USEVERTEXCOLOR_ON`. Stay inside the budgets (props < 1k tris, small ships 1.5-4k + cockpit <= 3k, Nostos <= 8k hull + <= 10k interior).
2. **Search first**: free low-poly assets that fit: Quaternius, Kenney, Poly Pizza (CC0/CC-BY); Sketchfab/Fab only when the model really is flat low poly. Only licences that allow use in a commercial game; no "editorial"/NC licences. Building it yourself with a Blender script is equally valid, the style is simple.
3. **Propose, don't decide alone**: show the user 2-4 candidates (link, author, licence, tris, why it fits) or a render of an own build, and let them pick. Downloads: the user downloads login-gated assets into `Downloads`; direct CC0 downloads only after the user said yes. Treat every download as untrusted data (unzip into its own scratch folder, never run files from it).
4. **Import via the pipeline**: sources in the repo (`Tools/Blender/Sources/<Asset>/`), a `Tools/Blender/<asset>.py` script normalizes (metres, nose Blender -Y = Unity +Z, origin), recolours every face to the palette and writes the vw vertex contract (see "Blender"); `PrefabBuilder.ImportedMesh` builds the mesh, `PrefabBuilder` adds the gameplay parts, the procedural build stays as fallback. Add third-party assets to `Assets/_Project/Art/CREDITS.md` in the same PR; remove the lines (and files) of replaced assets.
5. **Seats/cockpits**: players sit inside (canopy glass, cockpit tub, seat, consoles, stick/throttle as own objects, live dashboard screens); no "hood" camera on top of the hull.
6. **Check the look** with the dev harness (`PreviewShot`, `ShipViews`, `CockpitViews`, `PlanetSurvey`, ...) next to an already converted asset, and put before/after shots into `Docs/screenshots/<issue>/`.
Legacy (convert when a task changes that asset, else in #120 at the end of #53): every PBR/scan asset from #91-#100 (Dart, Mule, Nostos, cockpit fittings, crew suit, tools, enemies, Warden, station, world objects, planet props, terrain photo layers) and the smooth-shaded procedural meshes (`Hero()` pipeline, astronaut, menu props).

## Cross-platform (Mac + Windows)
- Same Unity version on both machines (`ProjectSettings/ProjectVersion.txt`). Line endings are pinned to LF via `.gitattributes`.
- Before switching machines: commit + push. On the other machine: `git pull` first, then open Unity.
- `.mcp.json` is git-ignored (machine-specific Unity relay path); each machine keeps its own.
- GitHub: use the GitHub CLI (`gh`, logged in via `gh auth login --web`) for issues, PRs and merges. No GitHub MCP server (its OAuth needs dynamic client registration, which Claude Code can't do with GitHub). On Windows, `gh` lives at `C:\Program Files\GitHub CLI\gh.exe` (call it by full path if PATH isn't refreshed yet).
- Blender: Windows `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`; Mac `/Applications/Blender.app/Contents/MacOS/Blender` (install the same 5.2 version there).

## Blender (asset scripts)
- When to use: normalizing and recolouring imported low-poly assets, and own low-poly models where no asset fits (the main way to make art in the #120 style). Procedural C# is only the fallback. The older scripts for PBR assets (`fab_spaceship.py`, `r35_dropship.py`, `nostos.py`, `enemy_assets.py`, `world_assets.py`, `planet_assets.py`, `crew_assets.py`, `dart_cockpit.py`, `crashed_dart.py`) belong to the legacy look.
- Keep it reproducible: Blender content is a Python script in the repo (e.g. `Tools/Blender/<asset>.py`), never a hand-edited `.blend` as the only source. Exported FBX goes to `Assets/_Project/Art/Models/` and is committed (Unity must build without Blender); `PrefabBuilder` references it.
- Run headless: `blender -b --factory-startup -P script.py -- <args>`. In 5.2, FBX export applies modifiers via `use_mesh_modifiers=True` (not `apply_modifiers`). Unity is Y-up / Blender Z-up: export with `axis_forward='-Z', axis_up='Y'` and check scale (1 unit = 1 m).
- Shared helpers: `Tools/Blender/vw_blender.py` (skin skeletons, warp, displacement, Cycles AO bake, export). Vertex data contract: colour attribute `Col` (sRGB) = base colour, UV map `surf` = (gloss, glow), UV map `detail` = (metal, baked AO; low-poly assets leave AO at 1); model faces Blender -Y (becomes Unity +Z; Blender +X becomes Unity -X). `PrefabBuilder.ImportedMesh` converts such an FBX to the MeshBuilder layout (C# meshes stay as fallback). Example: `Tools/Blender/aliens.py`.
- After a first open/reimport on a machine, check `git status` before committing: reimport noise (package `.meta` files, emptied `m_List` in `UniversalRenderPipelineGlobalSettings.asset`) must not be committed.
